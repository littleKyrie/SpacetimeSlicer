# 图片按帧与机位重组脚本计划

## Summary

设计一个 Python 命令行脚本，用于整理数据目录中的图片：

- 输入：一个包含若干原始图片的数据目录。
- 输出：在同一数据目录下生成按帧号命名的子目录，例如 `0001/`、`0002/`。
- 每个帧目录内按机位编号保存图片，例如 `001.jpg`、`002.jpg`。
- 执行前先将原始图片复制到 `原始图片/`，再生成一份标准化编号图片 `000.jpg`、`001.jpg`、`002.jpg`。
- 所有复制操作成功后，删除数据根目录下本次扫描到的原始图片。
- 实现前先将本计划保存为 `Docs/plan.md`。

## Key Changes

- 新增独立 Python 脚本，例如 `reorganize_frame_images.py`。
- 使用 `argparse` 提供参数：
  - `input_dir`：数据目录。
  - `--pre-frame-count`：进入特效段前的普通帧数量，默认 `125`。
  - `--camera-count`：特效段机位参数，默认 `90`。
  - `--original-dir-name`：原始图片备份目录名，默认 `原始图片`。
  - `--normalized-dir-name`：标准化编号图片目录名，默认 `重命名数据`。
  - `--image-ext`：输出图片扩展名，默认 `.jpg`。
  - `--dry-run`：只打印操作，不实际复制或创建目录。

## Processing Rules

- 图片发现与排序：
  - 扫描 `input_dir` 根目录下的图片文件。
  - 忽略已生成目录，例如 `原始数据/`、`重命名数据/`、`0001/`。
  - 从文件名中提取最后一组数字作为原始序号。
  - 按该数字升序排序。
  - 若序号重复，报错并停止。

- 原始图片保存：
  - 将扫描到的原始图片复制到 `input_dir/原始图片/`。
  - 在备份、标准化图片、帧目录图片全部复制成功后，删除数据根目录下的原始图片。
  - 若目标文件已存在，默认报错。

- 标准化命名：
  - 按排序结果复制到 `input_dir/重命名数据/`。
  - 文件名统一为 `000.jpg`、`001.jpg`、`002.jpg`。
  - 标准化编号表示源图片顺序，不表示帧号或机位号。

- 帧目录重组：
  - 前置普通段：
    - 源图片 `000.jpg` 到 `pre_frame_count - 1.jpg`。
    - 分别写入帧目录 `0001/` 到 `pre_frame_count`。
    - 每个目录内命名为 `001.jpg`。
    - 示例：`pre_frame_count=125` 时，`000.jpg` 写入 `0001/001.jpg`，`124.jpg` 写入 `0125/001.jpg`。
  - 特效帧：
    - 第 `pre_frame_count` 帧目录同时包含多机位画面。
    - 实际写入数量为 `camera_count + 1`，因为 1 号机位数据在普通段和特效段计算中被播放了两次。
    - 示例：`pre_frame_count=125`、`camera_count=90` 时，将源图片 `124.jpg` 到 `214.jpg` 全部写入 `0125/`。
    - 对应命名为 `001.jpg` 到 `091.jpg`：`124.jpg -> 001.jpg`，`125.jpg -> 002.jpg`，直到 `214.jpg -> 091.jpg`。
  - 后续普通段：
    - 从源图片 `pre_frame_count + camera_count` 开始继续。
    - 示例：`125 + 90 = 215`，所以源图片 `215.jpg` 写入 `0126/001.jpg`，之后依次递增。

## Validation And Edge Cases

- 若图片总数小于 `pre_frame_count + camera_count + 1`，报错。
- 若目标帧目录或目标图片已存在，默认报错，避免覆盖已有整理结果。
- 只处理常见图片扩展名：`.jpg`、`.jpeg`、`.png`、`.bmp`、`.webp`。
- 输出文件名统一使用 `.jpg` 后缀，但复制时不重新编码图片。
- 帧目录固定使用 4 位补零：`0001`、`0125`。
- 机位文件固定使用 3 位补零：`001.jpg`、`091.jpg`。

## Test Plan

- 使用临时目录构造 220 张假图片，验证按文件名最后一组数字排序。
- 验证 `pre_frame_count=125`、`camera_count=90` 时：
  - `0001/001.jpg` 来自标准化源 `000.jpg`。
  - `0125/001.jpg` 来自 `124.jpg`。
  - `0125/002.jpg` 来自 `125.jpg`。
  - `0125/091.jpg` 来自 `214.jpg`。
  - `0126/001.jpg` 来自 `215.jpg`。
- 验证重复序号时报错。
- 验证图片数量不足时报错。
- 验证 `--dry-run` 不创建目录、不复制文件。
- 验证 `--dry-run` 不删除根目录原始图片，只打印删除计划。
- 验证已存在目标文件时默认报错。

## Assumptions

- `camera_count=90` 表示特效段机位参数，不直接等于写入第 125 帧的图片总数。
- 特效帧实际写入 `camera_count + 1` 张图片。
- 原始图片会先复制到 `原始图片/`，成功完成全部复制后再从数据根目录删除。
- 标准化图片目录默认命名为 `重命名数据/`。
