# 人物切片黑边分析与修复计划

日期：2026-09-27。状态：方案阶段，尚未修改合成代码或重渲染成片。

## 1. 结论与推荐路线

两个样例分别呈现细暗轮廓和头顶较宽的不规则黑块。第 54 帧样例需要同时排查硬遮挡与切片颜色污染；新增第 22 帧样例更应优先排查**真人保护范围是否超出真实轮廓，以及二值化是否把这片区域变成了完全禁止切片的缺口**。

用户提出的“二值分界导致生硬边缘”有代码依据。但“边界不平滑”和“遮挡范围错误”是两个问题：羽化能缓和前者，不能保证修正后者。此处不把舞台背景为黑色本身作为缺陷原因；需要解释的是，为什么原本应该显示历史切片的位置留下了突变的空隙。

推荐先诊断遮挡范围，再做两个独立改动的对照，最后组合采用：

1. 用连续推理得到的原始 alpha、二值保护及无保护切片栈核对头顶缺口；区分误分割、阈值放大和膨胀。真人对切片的遮挡由硬阈值改为连续 alpha，并在整个切片栈上统一应用一次。
2. 切片使用 RVM 的前景颜色 `fgr`，而不是直接使用原始帧 RGB；统一用预乘 alpha、浮点数进行合成。
3. 若真人轮廓仍有明显暗边，再在重叠区域引入前景重合成与可信背景恢复。

单纯把二值 mask 高斯模糊、调大膨胀范围或提高分割阈值，不能同时解决颜色污染与遮挡关系。

## 3. 当前实现中的问题

### 3.1 真人遮挡使用硬阈值

位置：[models/spacetime_slicer.py](../models/spacetime_slicer.py)，`build_subject_protection_mask()`（约 594 行）、`compose_static_ghosts()`（约 629 行）、`compose_recovery_frame()`（约 611 行）。

```python
P = (alpha_mask > alpha_threshold)
ghost_alpha *= 1 - P
```

真人保护区内部完全禁止切片，外部立即允许切片。当前阈值 32 相当于归一化 alpha 约 0.125：一个边缘像素跨过这个值，就可能在两套不同画面之间突然切换。

如果保护区包含原图中的暗背景混合像素，这些暗像素会被保留下来；旁边出现较亮切片时就形成描边。较大的保护膨胀还可能把一圈真实背景一起保护，扩大空隙。

`patched_canvas` 的 `live_mask`（约 490 行）也使用二值阈值；它的 ghost burn（约 447 行）另有阈值裁切。这些是另一模式的相关问题，应同步规划，但不能在未核对生成参数时认定其为本例主因。

### 3.2 切片使用原始画面的颜色

位置：[models/rvm.py](../models/rvm.py)，`process_frame()`（约 23 行）。模型同时输出 `fgr` 与 `pha`，当前仅返回 8 位 alpha。`process_segment()` 保存的是 `current_frame`，后续以这个原图作为切片颜色。

源图边缘可写成：

```text
I = A * F + (1-A) * B_old
```

`F` 是前景颜色，`B_old` 是原背景，`A` 是真实覆盖率。把 `I` 当成纯前景再次按 `A` 合成，得到：

```text
C_wrong = A * I + (1-A) * B_new
        = A² * F + A*(1-A)*B_old + (1-A)*B_new
```

旧暗背景被带到新切片上，前景边缘也被再次衰减。该机制可以产生黑边；具体幅度取决于真实边缘颜色与模型估计。RVM 官方示例采用 `fgr * pha + background * (1-pha)`，支持优先对照 `fgr` 的方案；`fgr` 本身仍可能有估计误差。

### 3.3 多层合成和数值处理

当前切片按捕获顺序逐层叠加，较新的切片覆盖较旧切片。这个顺序是特效规则，并不代表真实三维深度，应保持规则明确。

每层之后立即转换 `uint8` 会产生反复舍入，但它更可能是次要因素。`interpolate_ghost()` 已有预乘 alpha 的插值思路，不应把整个项目描述成“完全没有正确的 alpha 插值”。后续应把这一思路统一到静态、回收和持久画布路径，并避免中间反复量化。

### 3.4 宽黑块需要额外排查的遮挡范围问题

对样例二按以下顺序提出假设；这是诊断优先级，并非已经确认的根因：

| 假设 | 为什么值得检查 | 区分方法 |
|---|---|---|
| 真人 alpha 在头顶轮廓外仍有中低值，低阈值把它扩成全保护区 | 例如 `A=0.20` 本来只是部分覆盖，但阈值 32 会将它变成 `P=1`，切片贡献直接归零 | 在源图上叠加原始 alpha 等值线与保护轮廓，检查暗块是否对应 `P=1`；比较连续保护 |
| 分割本身在头顶出现较大假阳性，或递归状态与快速动作不匹配 | 黑块大小随帧变化，存在不规则台阶；若 alpha 在错误区域已经接近 1，直接 `P=A` 仍会留下缺口 | 顺序重提取 alpha，与真实轮廓、上一帧形状对照；诊断性比较不同预热和逐帧重置，不能直接把重置设为正式方案 |
| 保护膨胀扩大了空隙 | 代码有独立的保护膨胀参数，生成时取值未知 | 固定 alpha 比较膨胀 0、1、2；当前全分辨率 3×3 核两次仅在每个坐标方向扩约 2 像素，不能单独解释数十像素宽的块，除非还有缩放或更大迭代 |
| 历史切片 alpha 自身缺失，或两层轮廓/坐标不匹配 | 即使不保护真人，切片也可能没有覆盖这一区域 | 检查无保护切片栈及每个切片的 alpha；记录当前帧/切片索引、尺寸和位置，排除 resize、错帧或 recovery 对齐问题 |
| 切片颜色问题 | 仍可能与缺口同时存在 | 固定 alpha/保护仅切换 `fgr`。如果暗块位于 `P=1`，更换切片颜色对该处没有作用 |

alpha 是前景覆盖率的估计，不是简单的分类置信度。真实运动模糊、半透明衣物与头发也有中间 alpha，不能为了去掉误分割就统一删除所有中间值。

因此，“二值过渡不平滑”很可能是**放大问题的环节**；宽黑块还可能要求修正输入 alpha 的空间范围。不能承诺仅加羽化就消除宽黑边。

## 4. 分阶段解决方案

### 阶段 A0：先定位头顶缺口来源

针对样例二增加一个不改正式算法的诊断分支，保存第 18–26 帧的原始 alpha、二值保护、切片叠加前后图和无真人保护的切片栈。输出真实有效参数与帧索引。

1. **只取消保护作定位**：如果历史切片填满头顶暗块，保护路径是主要嫌疑；如果暗块仍在，转查切片自身 alpha 与颜色。此分支允许切片覆盖真人，只用于归因。
2. **固定 alpha 对比二值与连续保护**：若 `P=A` 明显改善，说明二值化放大了中间值；若错误区域仍有大范围 `A≈1`，先修正 alpha，不能继续扩大羽化。
3. **独立扫描阈值与膨胀**：仅作诊断，阈值用 16/32/64/96，膨胀用 0/1/2，逐项变化。记录头顶缺口的范围变化以及真实前景被穿透的代价。
4. **复核时序与坐标**：按该视频实际生成顺序重提取，不跳过前置帧；如观察到滞后再做重置/预热对照。对每个切片检查源帧、尺寸、相机和位置。

### 阶段 A：软遮挡与统一切片栈

保持完整原始帧作为底图，先做改动范围较小的验证。

1. 将当前真人 alpha 归一化为 `A_live ∈ [0,1]`，第一版直接使用 `P=A_live`。
2. 如有孤立背景噪点，再使用轻量、连续的去噪映射；几何分析所需的二值 mask 不参与最终颜色合成。
3. 默认不膨胀保护区。若边缘存在局部错位，仅在边界窄带内验证尺度相关的处理，保留衣袖、头发、指尖与运动模糊。
4. 先把全部切片合成一个透明切片栈，再应用一次真人保护。静态与回收阶段复用同一逻辑。

针对样例二，可在 `P=A` 基线上额外试验连续映射：`P=smoothstep(low, high, A)`。首轮候选可用归一化 `low=0.05, high=0.95`，仅作为待验证值；它会减弱低值误保护、保留高值内部保护，但也改变真实半透明覆盖，需检查头发与运动模糊，不能直接定为默认。

如果已经确认 alpha 的高值范围错误，优先在头顶局部做带源图引导的 matte refinement，使用可信内核与已确认外部区域约束过渡带。引导图不够清晰时也可能失败；不能仅凭像素颜色偏黑就把它当背景，真实头发会被误删。局部小幅收缩仅作敏感性试验，不作为全人物统一腐蚀规则。

切片栈使用预乘颜色 `K` 和覆盖率 `a`，初值为 0。按既定顺序叠加第 i 个切片：

```text
a_i = A_i * opacity_i
K = F_i * a_i + K * (1-a_i)
a = a_i + a * (1-a_i)
```

随后与原始帧 `I_live` 合成：

```text
a_effective = a * (1-P)
C = K * (1-P) + I_live * (1-a_effective)
```

这里只把保护应用一次。若把连续 `(1-P)` 分别乘到每个切片再叠加，重叠切片的有效覆盖率会不断累积，真人边缘可能随切片数量变化，不能直接机械替换原来的二值 mask。

这一步可减轻边界跳变，但仍在原图混合色上合成，不能保证彻底消除暗边。

### 阶段 B：保留前景颜色并统一合成契约

1. 为分割接口增加明确的 matting 结果：`alpha`、可选 `foreground`、颜色范围与通道顺序。
2. RVM 同一次前向推理返回 `fgr` 和 `pha`，保持现有递归状态连续更新，避免为了颜色再推理一遍。
3. RVM 输出为 RGB；与 OpenCV 的 BGR 显式转换，避免颜色颠倒。
4. 历史切片、静态合成及回收插值都使用同一份前景颜色和 alpha。其他只返回 alpha 的策略保留原图颜色回退路径，并注明仍有背景污染风险。
5. 浮点处理预乘颜色与 alpha；opacity 只应用一次，中间不除 alpha，输出到视频 writer 前才裁剪、舍入为 `uint8`。
6. 先在当前颜色空间完成可对照修复；线性光合成作为后续独立质量选项验证，不能把 gamma 调整当作黑边修复的替代方案。

连续覆盖率与正确前景颜色共同决定边缘过渡。宽范围模糊 alpha 会扩散暗色像素，不能替代这一步。

### 阶段 C：重叠区域的真人前景重合成（按阶段 A/B 结果决定）

如果阶段 A/B 后切片间的黑边明显减轻，而真人与切片之间仍有暗轮廓，则需要处理真人源图已经混入背景的边缘。

建立可信背景 `B_clean`，先将切片叠上去得到 `T`，再把真人放在顶层：

```text
C_reconstructed = F_live * A_live + T * (1-A_live)
```

仅在真人边界与切片影响区域交集内启用重合成，区域外保留原图。局部处理的外边界使用连续权重，并验证不会产生新的拼接边。

对静态机位，可评估排除人物后的多帧背景估计。普通时间中值背景不保证干净：人物长时间停留、多个人遮挡、舞台灯光变化都会污染背景。`freeze/start` 帧也不是天然干净背景。

背景不可靠时，先保留阶段 A/B，不强行全画面替换或直接从 `I/A` 推算前景；小 alpha 区域会放大噪声。

### 阶段 D：仍有抖动时的边缘细化

仅在静态黑边解决后，评估窄带引导滤波或局部 matting refinement。若连续帧 alpha 抖动明显，再评估运动对齐后的时序稳定；不能直接平均不同帧的 mask，否则会造成拖尾。

RVM 本身已有时序状态，优先确保诊断与正式渲染的推理顺序一致，再增加额外时序处理。

### 策略选择参数：`edge_composite_strategy`

计划在 `configs/spacetime_slicer.json` 增加一个字符串参数，通过改这一个值切换基线与试验策略：

```json
{
  "edge_composite_strategy": "legacy"
}
```

以上是待加入现有配置的字段示例，不是完整配置文件。**本节仅为参数设计，当前程序尚未实现此字段；现在直接加入 JSON 会被配置解析器判为未知参数。** 实施时必须先接通解析与渲染分支，再将默认值 `legacy` 写入配置。旧配置省略此字段时，也必须自动采用 `legacy`。

#### 取值与对照关系

| 参数取值 | 保护/合成行为 | 前景颜色 | 对应试验 |
|---|---|---|---|
| `legacy`（默认） | 完整调用现有分支，保留二值保护、膨胀、阈值过滤、逐层运算和量化时机 | 原图 | 现有逻辑与基线 |
| `diagnostic_no_protection` | 仅取消 source 静态和回收阶段的真人保护，其他合成运算沿用基线 | 原图 | A0 定位切片缺口；仅诊断 |
| `soft_alpha` | `P=A_live`，统一浮点预乘切片栈，保护只应用一次 | 原图 | 阶段 A |
| `soft_smoothstep` | 使用阶段 A 的连续映射 `P=smoothstep(0.05,0.95,A_live)`，其余与 `soft_alpha` 相同 | 原图 | 连续保护内部的映射对照 |
| `foreground_only` | 保护规则、顺序和量化时机沿用基线，仅替换切片颜色；回收插值使用对应前景颜色 | RVM `fgr` | 阶段 B 的颜色对照 |
| `soft_foreground` | 与 `soft_alpha` 相同的连续保护与预乘合成 | RVM `fgr` | 阶段 A+B |

`soft_alpha` 同时引入统一切片栈与浮点合成，属于阶段 A 的完整方案对照；若需要进一步拆分数值精度的贡献，可在诊断脚本中固定 alpha 与保护规则单独比较，不再增加正式配置开关。

后续阶段实施完成后，可扩展取值 `refined_soft`（校正局部 alpha 后连续保护）和 `layered_recompose`（阶段 C 的前景重合成）。它们目前仅为预留设计，未实现时不能列入可运行 choices，也不能自动替换成其他策略。

#### 保持现有逻辑的要求

- 默认及 `legacy` 必须走原有代码路径，保留现有 `effect_base_mode`、模型调用顺序、alpha 精度、逐层 `uint8` 转换、切片顺序和输出帧数。不能先统一重构所有模式，再把新的近似行为叫作 `legacy`。
- 新策略明确指定时才启用新处理。`legacy` 不额外进行前景颜色转换、局部 refinement、时序预热或背景重建。
- 同一输入、有效参数、环境与模型结果下，省略字段和显式 `legacy` 的编码前帧应一致；MP4 文件字节不作为兼容性判据。
- 当前配置使用 `source + RVM`，可作为第一阶段支持范围。其他 `effect_base_mode` 在非 `legacy` 模式下应在渲染前明确报不支持，待相应画布路径接通后再开放，避免静态与回收阶段使用不同策略。
- `foreground_only`、`soft_foreground` 要求策略提供前景颜色；第一版可只支持 RVM。模型不支持时明确报错，不静默回退到原图，以免对照结果名不副实。

#### 与现有参数的关系

| 现有参数 | `legacy` / `foreground_only` | 连续保护策略 |
|---|---|---|
| `live_subject_alpha_threshold` | 保留当前含义与数值 | 不参与 source 真人保护；日志明确说明，不再把 alpha 二值化 |
| `live_subject_protect_dilate` | 保留现有膨胀行为 | 第一版要求为 0，防止重新引入扩大保护；当前配置已经是 0 |
| `edge_feather` | 保留原行为 | 仍按现有方式处理输入 alpha，首轮保持当前值 0；不把这个旧参数当新策略选择器 |
| `ghost_opacity_start/end` | 保持原值 | 保持原值，opacity 只应用一次 |
| `effect_base_mode`、`method`、帧范围、拉伸与编码参数 | 保持原值 | 对照时保持原值，生成参数另有记录的样例应先恢复其实际值 |

`diagnostic_no_protection` 不使用真人保护阈值与膨胀，但日志应明确标为无保护诊断。对于连续保护策略，若用户设置了非零保护膨胀，应在开始渲染前说明冲突并报错；不要悄悄忽略该值或把它应用到二值 mask 上。smoothstep 首轮采用上述固定候选值，如后续有充分依据再增加可调范围；初期只暴露一个策略选择参数。

#### 测试时的使用方式

恢复现有行为，只需把字段设为：

```json
"edge_composite_strategy": "legacy"
```

头顶宽黑块按以下顺序测试，其他参数保持不变：

1. `legacy`：保存基线编码前帧与有效参数。
2. `diagnostic_no_protection`：判断缺口是否来自真人保护。
3. `soft_alpha`：判断连续覆盖率能否缓和缺口。
4. `soft_smoothstep`：与 `soft_alpha` 比较低值误保护和真实模糊边缘的取舍。
5. `foreground_only`：单独检查切片颜色污染。
6. `soft_foreground`：评估组合方案。
7. 若 `soft_alpha` 中错误位置的 alpha 仍接近 1，再实施并测试 `refined_soft`，而不是继续调大羽化。

建议支持同名 CLI 参数 `--edge_composite_strategy`，遵循当前“命令行覆盖 JSON”的规则；批处理需确认该参数可以传递到 slicer。每次输出记录实际生效的策略、模型、阈值/膨胀是否参与、帧映射与其他参数快照，并使用不同输出目录或明确的结果清单对应各策略，避免误认历史视频。

## 5. 实施涉及的文件

| 文件 | 计划内容 |
|---|---|
| `models/seg_strategy.py` | 定义可选前景颜色与连续 alpha 的接口，兼容仅有 alpha 的策略 |
| `models/rvm.py` | 同一次推理保留 `fgr/pha`，明确 RGB/BGR 转换 |
| `models/spacetime_slicer.py` | 统一预乘切片栈、一次软保护、静态/回收/画布合成及插值 |
| `build_spacetime_slicer.py` | 接通 `edge_composite_strategy` 的 JSON/CLI 解析、choices 与传参；增加前景、连续保护、边界与编码前合成图诊断；修正诊断推理顺序 |
| `batch_run.py` | 核对策略参数的配置与 CLI 转发，确保批量渲染记录实际选择的策略 |
| `configs/spacetime_slicer.json` | 实施时新增 `edge_composite_strategy: legacy`，省略字段也默认 `legacy`；试验结果充分后再讨论默认值变更 |

当前 `edge_feather` 只有负值触发腐蚀，正值没有羽化实现。直接把它改为正数不会启用自然过渡。新方案应明确参数含义，避免继续让名称与行为不一致。

当前 alpha 提取为 8 位是精度限制，但不是“二值化”；保留 float alpha 与消除硬阈值是两个不同改动。4K 全幅 float32 前景约占 95 MiB/帧，alpha 约占 32 MiB/帧，不应直接把所有稠密轨迹帧改为全幅 float 缓存。应评估带边缘余量的 ROI 缓存、float16 缓存或只在计算时转 float，并记录缓存量化的取舍。

## 6. 验证与验收计划

### 6.1 可重复诊断

固定输入、相机、源帧范围、模型与所有有效参数，保存运行参数快照。重点检查源帧与输出帧的映射，不把插帧后的帧号直接当源帧号。

需输出第 48–61 帧和相关捕获切片（若当前配置成立，为第 25、45 帧）的原图、`pha`、`fgr`、旧二值保护、新连续保护、切片栈、编码前 PNG。

新增样例二输出第 18–26 帧，重点保留第 19、21、22、24 帧。相关捕获切片必须按真实运行记录确定，不能套用样例一的第 25、45 帧。额外保存头顶局部无保护切片栈、保护轮廓叠图，以及缺口内 alpha 的数值分布。

现有 `save_debug_extractions()` 只遍历请求的帧，会令 RVM 时序状态不同于正式渲染。诊断应从正式特效起始帧顺序推理至目标帧，只在需要的帧保存结果；后续如改变预热策略，基线和候选必须同时改变。

### 6.3 验收条件

- 在原始分辨率 100% 和局部放大下，袖子、肩部、裤腿重叠处不再出现突变式黑色描边；允许保留真实衣物阴影与头发暗色。
- 真人实心区域不被历史切片穿透，半透明/运动模糊边缘连续；切片顺序和既定透明度保留。
- 不出现宽光晕、被削细的指尖、衣袖缺口、前景颜色漂移或新的边界拼接痕迹。
- 连续播放第 48–61 帧，边界不随阈值跨越明显闪烁；同时检查回收、多人分离区域及切片捕获帧。
- 新增样例二：连续播放第 18–26 帧，头頂缺口不再忽宽忽窄；用原图/前景轮廓界定真实覆盖范围，测量轮廓外且历史切片本应有贡献的缺口面积与最大厚度，避免把正常头发或衣物暗面计为缺陷。数值目标需基线诊断后确定。
- 自动指标只作为辅助：在人工确认的边界窄带内统计异常暗色下陷及连续帧变化，结合源图排除真实阴影；本次尚未建立或报告改善百分比。
- 记录耗时和峰值缓存占用，避免质量修复造成不可接受的 4K 内存增长。
- 验证策略开关：省略字段和 `legacy` 的编码前帧一致；切换后按文档运行对应分支；不支持的模型/模式或未知取值在渲染前报错；静态、回收与批处理记录同一个有效策略。

## 7. 不建议作为首选的处理

- 单纯提高阈值、强腐蚀：可能暂时去掉边缘，同时损伤人物轮廓。
- 扩大真人保护膨胀：可能保留更多原背景，扩大暗色空隙。
- 对二值 mask 大范围模糊：可以软化跳变，但污染颜色依然存在。
- 强行把前景颜色提亮：会改变人物衣物、头发和正常阴影。
- 全局交叉淡化：改变整个画面透明度，不能修复空间上的前后遮挡。
- 直接用 Poisson/seamlessClone：此处需要保留多个半透明切片与遮挡关系，先解决 matting 与 alpha 合成；梯度融合不作为第一阶段。
